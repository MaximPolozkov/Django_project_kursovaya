# MailFlow — сервис управления рассылками

Курсовой проект на Django: получатели, сообщения, рассылки с отправкой по требованию, история попыток, статистика, регистрация с подтверждением email, роли «Пользователь» и «Менеджер», кеширование в Redis.

## Быстрый старт (Windows)

1. Создайте базу в PostgreSQL:

   ```sql
   CREATE DATABASE mailing_db;
   ```

2. Запустите Redis (через Docker):

   ```bash
   docker run -d --name redis -p 6379:6379 redis:7
   ```

   Если Redis нет, в `.env` можно поставить `CACHE_ENABLED=False` — кеш будет храниться в памяти.

3. Скопируйте `.env.sample` в `.env` и впишите пароль от PostgreSQL.
4. Запустите `setup.bat`. Скрипт установит зависимости, создаст миграции и таблицы, группу «Менеджеры», спросит email и пароль администратора и запустит сервер.
5. Откройте http://127.0.0.1:8000/

## Запуск вручную

```bash
poetry install
poetry run python manage.py makemigrations users mailing
poetry run python manage.py migrate
poetry run python manage.py create_groups
poetry run python manage.py createsuperuser
poetry run python manage.py runserver
```

## Возможности

### Часть 1

- **Получатели** `/recipients/` — email (уникальный), Ф. И. О., комментарий. Полный CRUD.
- **Сообщения** `/messages/` — тема и тело письма. Полный CRUD.
- **Рассылки** `/mailings/` — начало и окончание отправки, статус, сообщение, получатели. Полный CRUD.
  - Статус («Создана», «Запущена», «Завершена») пересчитывается методом `Mailing.update_status()` при каждом просмотре рассылки (`get_object` в `MailingDetailView`) и при открытии списка и главной.
  - Проверки формы: начало не в прошлом, начало раньше окончания.
- **Отправка по требованию** — кнопка «Запустить рассылку» на странице рассылки или команда:

  ```bash
  poetry run python manage.py send_mailing 5      # рассылка №5
  poetry run python manage.py send_mailing --all  # все, у которых сейчас период отправки
  ```

  Запуск разрешён только между `start_time` и `end_time`, иначе выводится ошибка. Для каждого получателя письмо уходит через `send_mail()`, а результат сохраняется как попытка: «Успешно» или «Не успешно» с текстом ошибки.
- **Попытки рассылок** — дата и время, статус, ответ почтового сервера, рассылка. Показываются на странице рассылки.
- **Главная** — всего рассылок, активных рассылок (статус «Запущена» и сейчас период отправки), уникальных получателей.

### Часть 2

- **Регистрация** `/users/register/` — аккаунт активируется после перехода по ссылке из письма. **Вход/выход**, **восстановление пароля** («Забыли пароль?» на странице входа), **профиль**.
- **Статистика** `/statistics/` — успешные и неуспешные попытки, отправленные письма, разбивка по рассылкам.
- **Права доступа**:

  | Роль | Что может |
  |---|---|
  | Пользователь | создавать, смотреть, изменять и удалять своих получателей, сообщения и рассылки; смотреть статистику своих рассылок |
  | Менеджер (группа «Менеджеры») | смотреть всех получателей и все рассылки (но не изменять и не удалять чужие), смотреть список пользователей `/users/`, блокировать пользователей, отключать рассылки |

  Добавить пользователя в менеджеры: `poetry run python manage.py create_groups --manager email@example.com` или в админке.

- **Кеширование**:
  - серверное — Redis (`CACHES` в `config/settings.py`): показатели главной (`home_stats`) и статистика пользователя (`user_stats_<id>`) хранятся `CACHE_TTL` секунд и сбрасываются сигналами при изменении данных и после запуска рассылки;
  - клиентское — заголовки `Cache-Control: private, max-age` на главной и странице статистики и `ConditionalGetMiddleware` (ETag и ответ 304 Not Modified, если страница не изменилась).

## Почта

По умолчанию письма печатаются в терминал, где запущен `runserver`: там видно и письмо подтверждения регистрации со ссылкой, и письма рассылок. Чтобы письма уходили по-настоящему, заполните SMTP-настройки в `.env` (пример для Яндекса — в `.env.sample`).

## Структура

- `config/` — настройки, общий `StyleFormMixin`
- `users/` — модель пользователя (вход по email), регистрация, подтверждение email, сброс пароля, профиль, список и блокировка пользователей, команда `create_groups`
- `mailing/` — модели, формы, контроллеры, сервисы (`services.py`: отправка, статистика, кеш), сигналы, команда `send_mailing`
- `templates/` — базовый шаблон, меню, общие шаблоны формы и удаления
